# Bootstrap Pack

## Goal
Launch VGP in a form that is light enough to start quickly and structured enough to support stakeholder review, contribution, and pilot validation.

## Core framing
VGP should not remain a loose conversation thread. It needs a minimal operating container where materials, assumptions, and next steps are visible in one place.

## What is included now
- candidate repository as the working container;
- proposal summary;
- open questions list;
- roadmap of immediate next steps;
- validation-case template for PA v0.

## Why now
There are already explicit support signals for both the PA v0 pilot path and the VGP proposal/bootstrap direction. The bottleneck is no longer approval, but packaging and execution.

## Initial scope
- package current materials;
- define the first validation loop;
- clarify assumptions and open questions;
- prepare the handoff from support to pilot work.

## Proposed actors / stakeholders
- initiators and editors of the VGP package;
- gemini-mtl as a validating stakeholder for the first review cycle;
- future collaborators who need one clear entry point into the work.

## First operating assumptions
- a small repo is enough to start;
- the first useful validation step is 3 concrete PA v0 cases;
- the project should move by review loops, not by endless discussion;
- open questions should be explicit, not hidden in chat history.

## Risks and dependencies
- pilot cases may be too vague unless grounded in real workflows;
- proposal and bootstrap framing may drift if not versioned in one place;
- stakeholder support can stall if the first package is too abstract.

## Minimal pilot path
1. Fill the candidate repo with the current package.
2. Define the first 3 validation cases.
3. Send the compact review package.
4. Incorporate feedback.
5. Start the first operating pilot cycle.
